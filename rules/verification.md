# Правила проверки

- Отделять PASS, FAIL, SKIP, NOT RUN, BLOCKED.
- Вывод PASS допустим лишь для действительно проведённой проверки; не принимать прошлый отчёт или слова агента за доказательство.
- Соотносить результаты с точным commit SHA, тестовым окружением и версией артефакта, если это релевантно.
- До релиза проверять сборку, тесты, регрессии, содержимое пакета, обязательные интеграции и release gates.
- Не скрывать красный тест, заменяя проверку на тривиальную.
- Если визуальное качество критично, проверять фактический рендер и целевые viewport, а не только статический код.
- Дизайн-spec-тесты подтверждают только проверенные ограничения токенов/кода; не подменяют визуальный рендер, доступность, измерения LCP/INP/CLS и утверждение владельца. См. [правила дизайна](design.md).
- Не считать PR готовым к merge без проверки его текущего состояния и актуального HEAD.
