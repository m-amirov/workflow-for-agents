# Качество, доказательства и безопасность

## Проверки

1. **Структура:** обязательные имена файлов и метаданные, корректные ссылки.
2. **Содержание:** конкретный триггер, шаги, ограничения, критерии, отсутствие конфликтов.
3. **Поведение:** положительные/отрицательные eval-кейсы и ручная приёмка.
4. **Интеграция:** установленный навык реально обнаруживается агентом в заданной среде.
5. **Регрессия:** изменение общих правил не ломает другие проверенные сценарии.

## Доказательства

Различать: `documented` (описано), `implemented` (есть файлы/код), `validated` (выполнена проверка), `released` (проверено и доступно в целевой среде). В отчёте указывать точные команды, среды, версии, результаты, пропуски и причины.

Для релизов нельзя выводить PASS из существования workflow, старого зелёного CI, необследованного ZIP или отчёта агента. Проверки относятся к exact HEAD/сборке.

## Безопасность

Не хранить секреты и приватные логи в публичном репозитории. Не запускать непроверенные скрипты из внешних Skills без аудита. Не расширять разрешения агента без необходимости. Использовать минимальные привилегии, review перед деструктивными действиями, явные ограничения на внешние вызовы.

## Приёмка

Выполнение checklists само по себе не доказывает качество: проверяющий фиксирует реальные действия и артефакты. Не проверенное описывается как `not run` или `unverified`.
