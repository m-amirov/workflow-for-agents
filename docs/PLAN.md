# Полный план Workflow for Agents

## 1. Цель и назначение

Построить единую версионируемую базу для Codex, Claude Code, Gemini CLI, локальных моделей и будущих агентов. Один раз найденный и проверенный подход становится доступным в других проектах без копирования больших промптов.

**Результат:** управляемые правила, переиспользуемые Agent Skills, регламенты процессов, библиотека знаний, шаблоны задач, роли агентов, инструменты и набор проверок качества.

**Не цель:** заменять документацию всех проектов, поддерживать собственную универсальную агентную платформу с первого дня или безусловно автоматически загружать каждую инструкцию.

## 2. Семь самостоятельных компонентов

| Компонент | Для чего | Когда загружается |
|---|---|---|
| Rules | Короткие постоянные ограничения и стандарты | Всегда, если применимы к окружению |
| Skills | Контекстно-активируемые действия, сценарии и скрипты | Когда задача соответствует описанию |
| Knowledge | Доказанные факты, разборы ошибок, решения, закономерности | По тематической необходимости |
| Playbooks | Регламенты комплексных задач | При запуске соответствующего процесса |
| Prompts | Шаблоны самодостаточных запросов | По выбору пользователя/агента |
| Agents | Роли, зона ответственности и границы полномочий | Для делегирования конкретной роли |
| Tools | Валидаторы, установщики и вспомогательные скрипты | Когда они реально требуются |

Дополнительно: `projects/` хранит индекс проектного опыта, `integrations/` — адаптеры разных агентов, `evals/` — регрессионные сценарии.

## 3. Границы ответственности

- Глобальные правила: компактные и устойчивые договорённости, а не длинные алгоритмы.
- Skills: `SKILL.md` с `name` и `description`, необязательными `references/`, `scripts/`, `assets/` и проверками.
- Knowledge: наблюдения, подтверждения, источники, границы применимости. Не превращать каждый случай в Skill.
- Playbooks: порядок действий, артефакты, критерии завершения, явные release gates.
- Prompts: цель, контекст, ограничения, реализация, acceptance criteria, реальные проверки.
- Project context: только устойчивые решения и ссылки; актуальный код и конфигурация живут в исходном репозитории.

## 4. Общие навыки разработки

Приоритетные навыки: `task-planning`, `codebase-exploration`, `root-cause-debugging`, `regression-testing`, `code-review`, `minimal-change`, `git-workflow`, `release-verification`. `git-workflow` требует начинать и заканчивать в `main`, а временные ветки удалять лишь после доказанного переноса результата.

Для интерфейсов: `visual-audit`, `responsive-design`, `interaction-design`, `accessibility-audit`, `browser-qa`.

Для специальных задач: `interactive-fiction`, `game-visual-integrity`, `drawing-editor`, `browser-automation`, `document-extraction`, `classification-quality`, `seo-calculators`, `content-pipeline`.

Полная спецификация назначений и статусов — в [SKILL_CATALOG.md](SKILL_CATALOG.md).

## 5. Работа Skill

Навык обнаруживается по краткому description; основной текст и ресурсы читаются по мере необходимости. Это снижает расход контекста. Навык должен содержать условия активации, конкретные шаги, ограничения, проверяемые критерии результата и ссылки на дополнительные ресурсы.

Пример: root-cause-debugging последовательно изучает логи и ошибку, воспроизводит сбой, локализует первопричину, вносит минимальное корректное изменение, добавляет regression coverage и сообщает **фактические** результаты.

## 6. Цикл накопления знаний

Задача → исследование → исправление → проверки → запись с доказательствами в Knowledge → только при повторяемости обобщение в Skill.

Для каждого инцидента нужны: симптомы, среда, воспроизведение, root cause (или статус гипотезы), решение, затронутые версии, ссылки на PR/коммиты/логи, регрессионная проверка и ограничения. Детали — в [KNOWLEDGE_LIFECYCLE.md](KNOWLEDGE_LIFECYCLE.md).

## 7. Подключение к агентам

Центральный репозиторий — исходник. Для Codex основными точками подключения служат глобальные инструкции `~/.codex/AGENTS.md`, проектный `AGENTS.md`, пользовательские Skills `~/.agents/skills/` и проектные Skills `.agents/skills/`. У других агентов своя конфигурация.

План: `scripts/install.ps1` устанавливает выбранные навыки; `scripts/sync.ps1` сверяет версии, выявляет локальные изменения и обновляет без потерь; адаптеры сохраняют единый исходный набор правил. Сначала копирование с манифестом/проверкой конфликтов, а не обязательные symlink. **Эти скрипты находятся в backlog до реализации и тестирования.**

MCP — отдельный механизм доступа к инструментам и данным; Skill описывает порядок их использования, а не заменяет инструмент.

## 8. Качество, версии и безопасность

- Каталог навыков с описаниями условий запуска, совместимости, статусами и связями.
- Статический валидатор metadata, ссылок, наличия файлов и тестов.
- Evals: позитивные/негативные триггеры, expected behavior, запрещённые действия, результаты.
- Ревью изменений глобальных правил и фиксированные версии для проектов.
- Не хранить секреты и персональные данные; разграничивать права на выполнение внешних действий.
- Не считать CI или release PASS без реальных проверок на exact commit/build.

## 9. Внедрение

**Этап 1 — Foundation:** структура, AGENTS.md, глобальные правила, каталог, 8–10 базовых Skills, установщик/синхронизатор, валидация.

**Этап 2 — Knowledge:** миграция проверенных наработок Ludory, Eskizno, Dachametr, Twork; специальные Skills, уроки, инциденты.

**Этап 3 — Automation:** проверка Skills в CI, извлечение кандидатов в знания из завершённых PR с проверкой человеком, адаптеры агентов, версионирование подключений, поиск по каталогу.

Оценка готовности и критерии — в [ROADMAP.md](ROADMAP.md).

## 10. Главное архитектурное правило

Не строить «мультиагентную платформу» ради самой платформы. Сначала надёжные небольшие Skills, понятное подключение и воспроизводимые доказательства качества. Новую автоматизацию создавать только для подтверждённой повторяющейся задачи.
