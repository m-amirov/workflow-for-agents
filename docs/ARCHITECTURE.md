# Архитектура и границы

## Слои

1. **Policy:** `AGENTS.md` и `rules/` — устойчивые ограничения.
2. **Capability:** `skills/` — выбираемые по необходимости навыки, скрипты и ресурсы.
3. **Process:** `playbooks/` — сценарии, включающие несколько навыков.
4. **Evidence:** `knowledge/` и `evals/` — опыт, обоснования, проверки.
5. **Interface:** `integrations/`, `prompts/`, `agents/` — связь с конкретными средами.
6. **Registry:** `docs/SKILL_CATALOG.md` и `projects/` — обнаружение и навигация.

## Что куда записывать

| Ситуация | Место |
|---|---|
| «Никогда не утверждай PASS без проверки» | rules/verification.md |
| «Как искать root cause» | skills/development/root-cause-debugging/SKILL.md |
| «Как провести релиз с воротами качества» | playbooks/release.md |
| «Что случилось с экраном на конкретном планшете» | knowledge/incidents/ |
| «Как выбирать рабочий набор для конкретного проекта» | projects/<project>/README.md |
| «Задание Codex на исправление бага» | prompts/templates/ |
| «Как интегрировать с Claude Code» | integrations/claude/ |

## Источник истины и конфликты

1. Непосредственно наблюдаемые данные, текущий код, тесты, логи и пользовательские решения важнее старого описания.
2. Проектные настройки могут уточнять общую методику, но не отменяют безопасность и обязанность честно сообщать результаты.
3. При конфликте явно зафиксировать несовместимые требования; не подменять информацию молчаливым выбором.
4. Центральная база не должна хранить ещё одну «актуальную копию» архитектуры приложения: только устойчивые паттерны и ссылки на первоисточник.
5. Факты из прошлого PR не считать фактами текущей версии без повторной проверки.

## Формат Skill

Папка навыка содержит `SKILL.md` с YAML frontmatter (как минимум `name`, `description`) и краткую инструкцию. Допустимы `references/`, `scripts/`, `assets/`. Стандарт: https://agentskills.io/specification

Описание должно отвечать «когда использовать» и помогать не активировать навык при нерелевантных задачах. Ключевые подробности хранить в references, не помещать весь контекст во frontmatter.

## Правила именования

- Пути/имена навыков — lowercase kebab-case.
- Навык: `skills/<category>/<skill-name>/SKILL.md`.
- Инцидент: `knowledge/incidents/YYYY-MM-DD-short-topic.md`.
- Решение: `knowledge/decisions/ADR-NNN-short-topic.md`.
- Тест: `evals/cases/<skill-name>/...`.
- При переименовании учитывать обратную совместимость установленных навыков и ссылок.

## Управление изменениями

Правила и общие Skills обновлять через изолированные изменения, описывать миграцию и влияние на проекты. Не вводить транзитивное подтягивание всего репозитория в контекст. Установка должна поддерживать выбор профиля и обнаружение конфликтов.
