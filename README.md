# Workflow for Agents

Центральная база правил, переиспользуемых навыков (Agent Skills), инструкций, инженерных регламентов и проверенных знаний для Codex и других ИИ-агентов.

> **Статус:** Foundation / приёмка выполнена в доступной локальной среде. Knowledge Stage 2 добавил source-bound local evidence для Eskizno/Twork и независимые повторные проверки двух pilot patterns; protected GitHub main с PR/squash, физические устройства и внешние platform gates остаются отдельными статусами, а не PASS по умолчанию.

## Принцип

**Один раз выработать подход → проверить → задокументировать → переиспользовать во всех проектах.** При этом агент получает только релевантные инструкции, а не всю базу сразу.

| Раздел | Назначение |
| --- | --- |
| `rules/` | Постоянные правила качества, безопасности, коммуникации и разработки |
| `skills/` | Задачные навыки в формате `SKILL.md` с ресурсами и скриптами |
| `knowledge/` | Подтверждённые решения, ошибки, исследования, уроки |
| `playbooks/` | Повторяемые процессы: разработка, расследование, PR, релиз |
| `prompts/` | Готовые шаблоны задач для агентов |
| `agents/` | Специализированные роли с ограниченной областью ответственности |
| `tools/` и `scripts/` | Инструменты, установщик, синхронизатор и валидатор |
| `projects/` | Указатели на контекст отдельных проектов без копирования их кода |
| `evals/` | Сценарии проверки поведения навыков |
| `integrations/` | Адаптеры Codex, Claude Code и других агентов |

## Быстрый старт (Windows / PowerShell)

Из корня клонированного репозитория сначала просмотреть изменения:

```powershell
.\scripts\install.ps1 -Scope user -Skills git-workflow,root-cause-debugging -DryRun
```

Затем установить выбранные Skills:

```powershell
.\scripts\install.ps1 -Scope user -Skills git-workflow,root-cause-debugging
.\scripts\sync.ps1 -Scope user -DryRun
.\scripts\sync.ps1 -Scope user
```

Для одного проекта используйте `-Scope project -ProjectPath 'C:\path\to\project'`. Установщик не перезаписывает существующие неменеджируемые каталоги, а синхронизатор останавливается при локальных изменениях и конфликтующих файлах. Полные инструкции и ограничения: [scripts/README.md](scripts/README.md).

**Важно:** установка Skill сама по себе не делает Git-правило постоянно действующим. Для Codex настройте глобальный/проектный `AGENTS.md` согласно [инструкции](integrations/codex/README.md).

├── rules/

│   ├── core/

│   ├── automation/
│   ├── design/
│   ├── content/
│   ├── research/
│   └── domain/
├── knowledge/{patterns,decisions,incidents,research,lessons}/
├── playbooks/
├── prompts/{codex,analysis,templates}/
├── agents/
├── projects/
├── evals/{fixtures,cases}/
├── integrations/{codex,claude,generic}/

Категории создаются по мере появления содержимого; пустые каталоги в Git не сохраняются. Исходный план описывает **целевую**, а не полностью внедрённую структуру.

## Начальные договорённости

- Стандарты и правила — короткие и постоянно применимые; Skills — небольшие и активируемые по необходимости.
- Единственный источник истины о текущем коде, конфигурации и тестах — репозиторий конкретного проекта.
- Не записывать гипотезы как установленные причины; все выводы сопровождаются доказательствами.
- Нельзя утверждать, что проверка/CI/релиз успешны, если они фактически не выполнены.
- **Main-first:** агент работает в `main` по умолчанию; временные ветки допускаются только при необходимости, а после успешного переноса в `main` безопасно удаляются. Если перенос заблокирован, ветка сохраняется. [Git workflow](skills/development/git-workflow/SKILL.md).
- Не хранить секреты, токены, cookies или персональные данные в публичной базе.
- Изменения этой базы должны проходить проверку и ревью перед широким распространением.
