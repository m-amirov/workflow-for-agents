# Playbook: проверка Pull Request

1. Получить фактические base/head SHA, дифф и описание PR.
2. Оценить требования, затронутые зависимости, нежелательные изменения и риск регрессий.
3. Проверить существующие тесты и наличие новых.
4. Проверить реальные CI workflow/checks именно для текущего HEAD.
5. Отдельно изучить визуальные артефакты и пользовательские сценарии, если интерфейс затронут.
6. Сформулировать findings с severity, точным местом и конкретным действием.
7. Если требуется merge, перед ним повторно проверить head, review comments и release gates.

**Нельзя:** утверждать «PR готов» только по сообщениям автора или старому PASS. Не проводить merge по умолчанию без соответствующего запроса.
