# Playbook: релиз и release gates

## Сбор доказательств

1. Установить точный source SHA, зависимости и версию.
2. Запустить обязательные unit/integration/e2e/визуальные проверки по реальному профилю проекта.
3. Проверить сборку, упаковку, содержимое и, при необходимости, контрольные суммы.
4. Проверить целевые платформы/SDK и отдельные требования дистрибуции.
5. Проверить отсутствие неразрешённых blocking issues.
6. Зафиксировать артефакты, команды, exit codes, CI runs и scope каждой проверки.
7. Объявить готовность только если **все обязательные gates реально пройдены**.

## Вердикты

- PASS: выполнены все обязательные проверки.
- FAIL: хотя бы один gate провален.
- BLOCKED: отсутствуют доступы, среда или обязательные сведения.
- NOT RUN: проверка не выполнялась — не считать её зелёной.

Нельзя молча снижать release gates, менять целевой commit после проверки или подменять production-сборку тестовым пакетом.
