# Playbook: перенести изменения в main и удалить временные ветки

**Trigger:** завершение работы с Git, PR или временным worktree. Политика — `main-first`.

1. Узнать SHA `origin/main`, branch SHA, PR state и статус обязательных CI/review gates.
2. Зафиксировать все изменения; проверить `git status` и отсутствие чужой незавершённой работы.
3. Убедиться, что необходимые тесты реально выполнены на текущем HEAD.
4. Если работали в отдельной ветке, объединить результат с `main` через разрешённый merge/PR; не обходить branch protection.
5. Проверить содержимое `main` и точный итоговый SHA. При squash сверить статус merged PR и эквивалентность итоговых изменений.
6. Проверить, что временная ветка принадлежит **этой** задаче и не содержит неперенесённую работу.
7. Вернуться на `main`, если возможно и безопасно. Удалить локальную ветку через `git branch -d <branch>` лишь при подтверждённой ancestry. Не применять `-D` автоматически.
8. Удалить свою удалённую временную ветку (`git push origin --delete <branch>`) только после подтверждённого merge. Проверить очистку через fetch/prune.
9. Сообщить статус: `main SHA`, checks, удалённые/оставшиеся ветки, ограничения.

Если `main` защищена, PR ещё не смержен, CI красный, branch SHA неизвестен, есть чужие изменения или нельзя доказать полный перенос — **не удалять ветку**, сообщить `BLOCKED` и точную причину.
