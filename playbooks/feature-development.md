# Playbook: разработка функциональности

**Trigger:** запрос на новое поведение продукта.

1. Исследовать кодовую базу, тесты, пользовательские требования, ограничения.
2. Зафиксировать цель, non-goals, acceptance criteria и риски.
3. Определить минимальный набор модулей, который действительно нужно менять.
4. Реализовать вертикально работающий сценарий без ненужного переписывания архитектуры.
5. Проверить обычный путь, ошибки, границы данных, мобильные/desktop сценарии, если релевантно.
6. Добавить тесты для ключевого поведения.
7. Осмотреть дифф, провести review и подготовить отчёт.

**Готово:** изменение работает и подтверждено проверками; нерешённые пункты явно названы. CI/площадочный релиз — отдельные ворота.
