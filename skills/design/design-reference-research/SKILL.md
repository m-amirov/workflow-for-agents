# Design Reference Research

## Trigger
A new screen, visual direction or redesign needs grounded references. Read existing project instructions, approved design constraints, audience, primary action and relevant viewports first.

## Procedure
1. Find 3–5 relevant **live** examples where proportional to the task; include cross-industry analogues when they solve the same user goal.
2. Open and inspect each available reference at desktop and mobile sizes. Record URL, date, viewport, observed layout, spacing, typography, color roles, component states and responsive behavior. Mark inaccessible or unmeasurable properties **NOT VERIFIED**; no invented pixel measurements or conversion claims.
3. Select separate **structure donor** (content hierarchy, user path) and **visual donor** (grid, type and spacing); document what not to transfer.
4. Compare with the project's approved `DESIGN.md` or equivalent. Keep measurements as proposals; ask for design approval before replacing approved tokens or introducing a recognizable near-copy.
5. Supply a compact reference matrix, screenshots/links when actually captured, recommended direction and unresolved assumptions.

## Constraints
Transfer reusable principles, not logos, copyrighted artwork, proprietary text, brand identity or a whole distinctive page. Do not authorize component imports or implementation by researching a reference.

## Verification
State which pages, viewport sizes and observations were directly inspected. A link list is research input, **not** proof of design quality or browser QA.
